# Разработка игры

Заготовка платформера на TypeScript и Canvas 2D. Сейчас доступны движение героя,
прыжок, анимации и демонстрационная сцена.

## Управление

**A/D** или **←/→** — движение, **Space** — прыжок.
Canvas получает фокус при подключении и по клику.

## Структура

```text
Game/
├── Game.tsx                          # Контейнер игры
├── game.module.css                   # Стили
├── constants.ts                      # Константы для Canvas
├── helpers.ts                        # drawPreview и drawAnimation
├── components/
│   └── GameCanvas/
│       ├── GameCanvas.tsx            # Canvas сцена
│       └── game-canvas.module.css
├── hooks/
│   └── useGameCanvas.ts              # Жизненный цикл игровой сессии
└── utils/
    ├── gameLoop.ts                   # Фиксированный шаг и requestAnimationFrame
    ├── keyboard.ts                   # Клавиши, фокус и очистка обработчиков
    ├── loader.ts                     # Загрузка изображений с кешем
    ├── manifest.ts                   # Файлы спрайтов и описания анимаций
    └── player.ts                     # Состояние и движение героя
```

`pages/GamePage/GamePage.tsx` только подключает `<Game />`. Игровая логика
находится в этой feature. Новые вложенные компоненты размещаем в `components`,
хуки — в `hooks`, остальные игровые функции — в `utils`.

## Как работает игровая сессия

1. `GameCanvas` вызывает `useGameCanvas` и передаёт возвращённый ref в Canvas.
2. Хук получает контекст `2d`, создаёт героя, управление и игровой цикл.
3. До загрузки изображений `drawPreview` показывает сообщение загрузки.
4. `loadGameImages` загружает все изображения из `spriteFiles`. Только после
   успешной загрузки запускается симуляция. При ошибке выводится сообщение.
5. В `update` обновляются время сцены и герой. В `render` вызывается `drawPreview`.
6. Скрытие вкладки останавливает цикл и сбрасывает клавиши. При возвращении цикл
   продолжается без обработки времени, проведённого в скрытой вкладке.
7. При размонтировании останавливается цикл и удаляются обработчики событий.
   Результат незавершённой загрузки больше не применяется к этой сессии.

Потеря фокуса окна или Canvas сбрасывает клавиши, но сама по себе не останавливает
симуляцию. Остановка связана с `document.hidden`.

Состояние симуляции хранится в обычных переменных внутри эффекта, а не в React
state. Не вызывайте React-перерисовку на каждом кадре. При повторном подключении
компонента создаётся новая сессия; кеш изображений сохраняется на уровне модуля.

## Время, координаты и отрисовка

- Внутреннее разрешение — **640×360**, CSS сохраняет пропорции 16:9.
- Начало координат — левый верхний угол; X растёт вправо, Y — вниз.
- Координаты и скорости измеряются в игровых пикселях и пикселях в секунду.
  `deltaSeconds` передаётся в секундах.
- `update` работает с шагом `1 / 60` секунды. За один кадр браузера может быть
  несколько обновлений или ни одного. `render` вызывается раз в кадр браузера.
- Время долгого кадра ограничено 0,1 секунды, чтобы не выполнять слишком много
  обновлений сразу. Во время сильных задержек часть прошедшего времени отбрасывается.
- Логику движения меняем в `updatePlayer`, рисование — в `helpers.ts`.
  Отрисовка не должна менять физическое состояние героя.
- `drawAnimation` рисует кадры с масштабом ×2 и без сглаживания. Его X/Y задают
  середину нижнего края **кадра**, а не хитбокса. `facingLeft` отражает изображение.
- У героя X/Y обозначают точку у ног. Для спрайта рыцаря отрисовка получает
  `player.y + 8`, компенсируя прозрачный отступ снизу кадра.

Функции рисования принимают объект аргументов:

```ts
drawPreview({ context, images, elapsedSeconds, player });

drawAnimation({
  context,
  images,
  clip: animations.knightIdle,
  elapsedSeconds: player.animationTime,
  x: player.x,
  y: player.y + 8,
  facingLeft: player.facingLeft,
});
```

## Герой и управление

`createPlayer` задаёт начальное состояние. `updatePlayer` изменяет переданный
объект: скорость, координаты, направление, приземление и состояние анимации.
Параметры скорости, ускорения, торможения, гравитации и прыжка находятся в
`utils/player.ts`.

`jumpPressed` — одноразовый запрос: `updatePlayer` сбрасывает его после обработки.
Удержание Space не повторяет прыжок; в воздухе запрос не сохраняется до посадки.
При одновременно нажатых направлениях герой тормозит.

Состояния анимации: `idle`, `run`, `air`. При смене состояния время анимации
сбрасывается. Для воздуха пока используется первый кадр покоя.

## Добавление спрайтов и анимаций

1. Положите изображение в `packages/client/public/game-assets/sprites`.
2. Добавьте имя файла в `spriteFiles` в `utils/manifest.ts`. Загрузчик сам включит
   его в общий набор. Сейчас все перечисленные изображения обязательны для старта.
3. Для анимации добавьте описание в `animations`: `sprite`, `frameWidth`,
   `frameHeight`, `row`, `frameCount`, `fps`, `loop`.
4. Передайте описание в `drawAnimation` и подключите нужное состояние в логике героя
   или другого объекта.

Размеры кадров задаются в исходных пикселях. Строки нумеруются с нуля.
Сейчас кадры читаются слева направо, начиная с первого столбца выбранной строки.
Не включайте в `frameCount` текстовые подписи на листе. При `loop: false`
анимация останавливается на последнем кадре. Для запуска новой анимации сначала сбросьте её время;

Загрузчик формирует URL через `import.meta.env.BASE_URL`. Он кеширует Promise по URL, поэтому параллельные запросы не дублируют загрузку. Неудачная загрузка
удаляется из кеша; повторный вход на страницу повторяет запрос.

Изображения лежат в `packages/client/public/game-assets/`.

## Что ещё не реализовано

- Платформы, слизни и монета пока только нарисованы: столкновений и взаимодействий нет.
- Земля — временное ограничение `GROUND_Y = 296`; герой также ограничен краями экрана.
- Нет полноценного хитбокса, карты уровня, камеры, урона, сбора предметов и победы.
- Нет пользовательской паузы, рестарта, сохранений и мобильного управления.
- При уходе со страницы состояние игры теряется.

Следующий пункт — **коллизии** (?):

1. Описать хитбокс героя и прямоугольные твёрдые блоки.
2. Разрешать столкновения отдельно по X и Y, обнуляя соответствующую скорость.
3. Определять `grounded` по опоре под героем, включая сход с края платформы.
4. Заменить временную землю реальными блоками и рисовать их из тех же данных,
   которые использует физика.
5. Вручную проверить стены, потолок, посадку на платформу, её края и повторный прыжок.

После коллизий: уровень из данных и камера, поведение врага, сбор предметов,
игровой сценарий с победой/поражением и перезапуском.
